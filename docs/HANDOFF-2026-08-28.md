## O que bloqueou

- **Ahrefs** e **Semrush** (checkers gratuitos de autoridade): o submit é engolido
  por detecção de bot — nenhuma requisição de consulta sai. Não se contorna.
- **Seobility**: desafio Cloudflare ("Just a moment...").
- **API do PageSpeed sem key**: HTTP 429 persistente (quota por IP).
- **Mentionable** (GEO): navegação negada.

**Adendo (mesma tarde): o "7/100" foi CONFIRMADO.** O Mario rodou o checker do
Ahrefs à mão e o resultado é **DR 7**, com **999 backlinks de 593 sites — só
13–14% dofollow**. O número do vendor era verdadeiro; a composição mostra que o
gargalo não é volume de link, é qualidade (~86% nofollow não transfere
autoridade). Contexto de leitura: DR 1–15 é a faixa normal de B2B pequeno sem
link building; DR/DA/AS não são comparáveis entre si; nenhuma é fator de
ranking. Autoridade sobe com backlink dofollow de domínio relevante — imprensa,
artigos convidados, associações — não com mudança no site.

## Leitura

Dois auditores externos independentes (SEOptimer On-Page **A-**, Lighthouse SEO
**100**) contradizem a alegação de "ausência de pré-otimização básica de SEO
on-page" — o que confirma a tese de que o pendente (issues #13–#17) é
refinamento, não resgate. Os dois achados novos que valem investigação própria:
o **F de Usability** do SEOptimer (sem detalhe acessível) e o **LCP 5,9s mobile**
/ **CLS 0,466 desktop** do Lighthouse — performance, não SEO.

## Lição de ferramenta (para o próximo agente)

O pane do navegador in-app morre a cada fronteira de turno nesta instalação:
qualquer fluxo de navegador precisa caber **num turno só** (preview_start →
batch com wait/resize/read_page → batch com as ações usando os refs). Clique por
coordenada exige screenshot prévio, que falha com o pane invisível — use refs.
Páginas com análise JS pesada (pagespeed.web.dev) congelam os timers em pane
invisível; para elas, API ou CLI local.
